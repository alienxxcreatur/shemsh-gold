# بسته تصمیم OQ-058 — دسترسی فلز در معامله و نمودار

آخرین به‌روزرسانی: ۱۸ مرداد ۱۴۰۵ / 9 Aug 2026  
وضعیت: **`Complete` — ساختار D-120، قرارداد D-121 و پیش‌فرض طلای معامله D-123**  
دامنه: Release اول با طلا، نقره و مس؛ Stress state تا حدود ۱۶ فلز  
مسیر موازی: تأیید مالی/حسابداری OQ-055 طبق D-118 جداگانه ادامه دارد؛ Foundations عمومی مرحله ۷ طبق D-117 حفظ شده است

## هدف

انتخاب یک قرارداد دسترسی که:

- در سه فلز Release اول سریع و روشن باشد؛
- بدون بازطراحی ساختاری تا حدود ۱۶ فلز ادامه پیدا کند؛
- فلز فعال معامله و نمودار را بدون ابهام نشان دهد؛
- هیچ فلزی، از جمله طلا، پیش‌فرض هویتی محصول نشود؛
- در موبایل، PWA، Android WebView، وب عریض و Deep Link رفتار قابل توضیح داشته باشد.

این سند الگوهای محلی معامله و نمودار را پوشش می‌دهد. گزینه ۱ ساختار کل اپ با D-120 و اصلاح D-215 تأیید شده است؛ بنابراین مدل منتخب داخل شل ثابت `خانه / معامله / خدمات` و Template مشترک جزئیات فلز اجرا می‌شود. مقصد مستقل بازار/همه فلزها وجود ندارد.

## غربال گزینه‌ها پس از تأیید ساختار کل اپ

D-120 نقش گزینه‌ها را روشن‌تر کرده است:

- مدل C دیگر ورودی اجباری تب معامله نیست؛ با D-215 مقصد «بازار/همه فلزها» نیز حذف شده و تب معامله مستقیم و سریع می‌ماند.
- مدل A برای Release اول سه‌فلزی سریع است، اما در ۱۶ فلز به Scroll افقی و مسیر دوم جست‌وجو وابسته می‌شود؛ بنابراین قرارداد پایه نیست.
- مدل D دو روش هم‌زمان برای انتخاب فلز ایجاد می‌کند و در سه فلز تکراری است؛ فقط اگر تست واقعی بعداً اصطکاک تعویض فلز را ثابت کرد، می‌تواند لایه سرعت روی مدل اصلی باشد.
- مدل B تنها Candidate پایه باقی می‌ماند: انتخاب‌گر واحد در صفحه + Sheet کامل در موبایل و Popover/Dialog فهرستی در وب عریض.

این غربال با D-121 تأیید و به قرارداد قطعی طراحی تبدیل شد.

## مرجع طراحی

- [Apple HIG — Segmented controls](https://developer.apple.com/design/human-interface-guidelines/segmented-controls) توصیه می‌کند تعداد Segmentها محدود بماند و روی iPhone حدود پنج گزینه بیشتر نشود؛ بنابراین Segment ثابت، قرارداد مناسبی برای ۱۶ فلز نیست.
- [Apple HIG — Search fields](https://developer.apple.com/design/human-interface-guidelines/search-fields) جست‌وجوی درون‌زمینه‌ای نزدیک فهرست، نتیجه هم‌زمان با تایپ و پیشنهادهای مرتبط را توصیه می‌کند.
- [Material Design — Canonical layouts](https://m3.material.io/foundations/layout/canonical-examples/overview) الگوی list-detail را برای توسعه یک ساختار مشترک از عرض فشرده تا عریض معرفی می‌کند.
- خروجی محلی UI/UX Pro Max: هدف لمسی حداقل ۴۴px، فاصله حداقل ۸px، Active state صریح، Back قابل پیش‌بینی، پرهیز از وابستگی به Swipe افقی، و Line chart برای روند زمانی با تمایز غیررنگی سری‌ها. قرارداد شمش هدف لمسی ۴۸px را حفظ می‌کند.

## خط مبنا — Segment یا Tab ثابت

```text
┌──────────────────────────────┐
│  [ طلا ] [ نقره ] [ مس ]     │
│  خرید | فروش                 │
│  مبلغ / وزن                  │
└──────────────────────────────┘
```

برای سه فلز سریع و واضح است، اما در ۱۲ یا ۱۶ فلز یا فشرده، اسکرولی و چندردیفه می‌شود. این مدل **گزینه نهایی نیست**؛ فقط خط مبنای سرعت Release اول است.

## مدل A — ریل افقی فلزها + جست‌وجو

```text
┌──────────────────────────────┐
│ [طلا][نقره][مس][پلاتین] … [⌕]│
│          نقره • فعال         │
│  خرید | فروش                 │
└──────────────────────────────┘
```

### رفتار

- همه فلزها در ریل افقی هستند؛ فلز فعال Active state صریح دارد.
- برای ۷+ فلز، دکمه جست‌وجو فهرست کامل را باز می‌کند.
- آخرین موقعیت Scroll و فلز فعال حفظ می‌شود.

### مزیت

- تعویض فلز پرتکرار با یک Tap.
- سه فلز Release اول هم‌زمان دیده می‌شوند.

### ریسک

- فلزهای خارج View کشف‌پذیری ضعیف‌تری دارند.
- Swipe افقی با Gesture سیستم، نمودار یا Back تعارض بالقوه دارد.
- در RTL تشخیص ابتدا/انتها و بازگشت به فلز قبلی نیازمند تست بیشتر است.
- با ۱۶ فلز، جست‌وجو عملاً راه اصلی می‌شود ولی ریل همچنان فضای صفحه را مصرف می‌کند.

## مدل B — انتخاب‌گر واحد + فهرست کامل در Sheet

```text
┌──────────────────────────────┐
│  فلز معامله                  │
│  [ نقره  Ag      فعال   ▾ ]  │
│  خرید | فروش                 │
│  مبلغ / وزن                  │
└──────────────────────────────┘

        با Tap روی انتخاب‌گر

┌──────────────────────────────┐
│  انتخاب فلز              ×   │
│  [ جست‌وجوی نام یا نماد ]     │
│  ○ طلا       Au     فعال     │
│  ● نقره      Ag     انتخاب‌شده│
│  ○ مس        Cu     اختلال نرخ│
│  …                           │
└──────────────────────────────┘
```

### رفتار

- انتخاب‌گر همیشه نام، آیکن/نماد و وضعیت فلز فعال را نشان می‌دهد.
- در موبایل، Modal Bottom Sheet یا صفحه انتخاب تمام‌قد؛ در وب عریض، Popover/Dialog فهرستی.
- ساختار Sheet در ۳ و ۱۶ فلز یکی است؛ فقط از ۷ فلز به بالا Search به‌صورت پیش‌فرض نمایش داده می‌شود.
- ترتیب از `AssetCatalog` خوانده می‌شود و Search نام فارسی، نام لاتین و نماد را پوشش می‌دهد.

### مزیت

- مقیاس‌پذیری واقعی بدون فشرده‌کردن کنترل اصلی.
- فلز فعال و status آن همیشه کنار فرم معامله روشن است.
- فهرست می‌تواند نرخ، مالکیت، اختلال و قابلیت معامله هر فلز را بدون شلوغ‌کردن صفحه اصلی نشان دهد.
- یک Component مشترک در معامله، نمودار و جزئیات دارایی قابل استفاده است.

### ریسک

- تعویض فلز نسبت به Tab یک Tap بیشتر دارد.
- برای سه فلز ممکن است در نگاه اول کمی سنگین به نظر برسد.
- کیفیت Sheet و حفظ Focus/Back برای دسترس‌پذیری حیاتی است.

## مدل C — بازار فلزها به‌عنوان صفحه Master، معامله به‌عنوان Detail

```text
┌──────────────────────────────┐
│ بازار فلزها      [ جست‌وجو ] │
│ طلا     نرخ / تغییر / status │
│ نقره    نرخ / تغییر / status │
│ مس      نرخ / تغییر / status │
│ …                           │
└──────────────────────────────┘
            ↓ انتخاب
┌──────────────────────────────┐
│ نقره  Ag                     │
│ نمودار  | خرید | فروش        │
└──────────────────────────────┘
```

### رفتار

- ورود مستقیم به معامله ابتدا فهرست بازار را نشان می‌دهد؛ انتخاب ردیف وارد Detail همان فلز می‌شود.
- در وب عریض، فهرست و Detail می‌توانند کنار هم باشند؛ در موبایل، دو صفحه با Back مرحله‌ای‌اند.
- Deep Link مستقیماً Detail فلز مشخص را باز می‌کند.

### مزیت

- بهترین مدل برای کشف، مقایسه نرخ/status و توسعه تعداد فلزها.
- رابطه List → Detail در موبایل و دسکتاپ واضح است.
- برای کاربری که هنوز نمی‌داند چه فلزی می‌خواهد، تصمیم‌گیری قوی‌تر است.

### ریسک

- معامله تکراری یک مرحله بیشتر دارد.
- Tab «معامله» بخشی از نقش «بازار» را هم می‌گیرد و مدل ذهنی فعلی D-094 را تغییر می‌دهد.
- Scope صفحه و داده بازار بزرگ‌تر و هزینه Prototype/Test بیشتر می‌شود.

## Context معامله و نمودار

`Business decision`: انتخاب معامله و نمودار **دو State مستقل** هستند — D-121:

- `tradeAssetId`: آخرین فلز انتخاب‌شده در معامله.
- `chartAssetId`: آخرین فلز مشاهده‌شده در نمودار.
- ورود contextual با `assetId` بر State همان مقصد اولویت دارد.
- مشاهده نمودار مس نباید بی‌صدا فرم معامله نقره را به مس تغییر دهد.
- CTA صریح «معامله این فلز» از نمودار، `assetId` را به معامله منتقل می‌کند.
- نمودار داخل Template جزئیات فلز، `assetId` همان صفحه را می‌گیرد و انتخاب جدا نمی‌خواهد؛ استقلال `chartAssetId` فقط برای نمودار مشترک خانه یا مقصدی خارج از جزئیات فلز کاربرد دارد.

## مدل‌های نمودار

### N1 — نمودار تک‌فلز

- Line chart یک `chartAssetId` با انتخاب‌گر مدل B.
- نرخ، تغییر مبلغ/درصد، وضعیت داده و بازه همان فلز.
- بهترین خوانایی موبایل و کمترین احتمال مقایسه گمراه‌کننده.

### N2 — چند خط با قیمت خام

- قیمت هر گرم چند فلز روی یک محور.
- به‌علت اختلاف شدید مقیاس قیمت، خط فلز ارزان‌تر ممکن است تقریباً صاف دیده شود.
- **برای مقایسه رد می‌شود.**

### N3 — مقایسه نرمال‌شده درصد تغییر

- همه سری‌ها از ابتدای بازه روی صفر درصد تنظیم می‌شوند.
- مناسب پاسخ به «کدام فلز در این بازه بهتر حرکت کرده؟» نه مقایسه قیمت واقعی.
- در موبایل حداکثر ۳ سری، با Legend، Label و Line style متفاوت؛ رنگ تنها شناسه نیست.
- Candidate آینده، نه نیاز قطعی Release اول.

### N4 — Small multiples

- چند نمودار کوچک با مقیاس مستقل در Grid/List.
- برای صفحه بازار یا وب عریض مفید است؛ در موبایل Release اول فضای زیاد و مقایسه دقیق ضعیف‌تری دارد.

## قرارداد تأییدشده OQ-058 برای نمودار

`Business decision` — D-121:

- Release اول: **N1، نمودار تک‌فلز** با همان خانواده انتخاب‌گر مدل B.
- مقایسه چندفلزی وارد Release اول نشود.
- معماری داده برای N3 محفوظ بماند؛ اگر بعداً اضافه شد فقط درصد تغییر نرمال‌شده، نه قیمت خام، و حداکثر سه سری روی موبایل باشد.
- نمودار خانه `chartAssetId` مستقل دارد؛ هیچ نموداری هنگام مرور، `tradeAssetId` را بی‌صدا تغییر نمی‌دهد.

`Business decision`: **R4 — روزانه، ماهانه و سالانه** برای نمودار هر فلز — D-121. بازه‌ها از Config خوانده شوند؛ اگر داده معتبر یک بازه برای فلزی وجود ندارد، همان بازه با توضیح unavailable باشد و بازه دیگری بی‌صدا جایگزین نشود. تعریف فنی نمونه‌برداری هر بازه در قرارداد داده مرحله بعد تکمیل می‌شود.

## قرارداد Component و داده پیشنهادی

```text
AssetSelector {
  surface: trade | chart | asset_detail
  selectedAssetId
  catalogOrder
  searchable
  searchThreshold: 7
  rows[] {
    assetId
    displayName
    officialIcon
    symbol
    marketStatus
    tradeCapability
    priceStatus
  }
}

AssetContext {
  source: direct | home_position | asset_detail | alert | deep_link
  assetId
  defaultTradeAssetId
  lastTradeAssetId
  lastChartAssetId
}
```

- Search نام فارسی، نام لاتین و Symbol را پشتیبانی کند.
- ترتیب فهرست پایدار و Config-driven باشد؛ Recent/Pin تا تصمیم مستقل وارد Release اول نشود.
- ردیف فلز دارای اختلال حذف نشود؛ status و اثر بر معامله نشان داده شود.
- Search نتیجه خالی همراه پیشنهاد پاک‌کردن Query/مشاهده همه فلزها داشته باشد.
- Target لمسی حداقل ۴۸×۴۸px، فاصله حداقل ۸px و Focus/Screen-reader label الزامی است.
