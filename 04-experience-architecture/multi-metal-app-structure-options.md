# گزینه‌های ساختار کل اپ چندفلزی

آخرین به‌روزرسانی: ۲۸ مرداد ۱۴۰۵ / 19 Aug 2026
وضعیت: **گزینه ۱ با اصلاح D-215 فعال است — شل و جزئیات مستقیم حفظ، مقصد همه فلزها حذف**
دامنه: شل، خانه، دارایی، معامله، نمودار، خدمات و تاریخچه؛ Release اول با ۳ فلز و Stress state تا حدود ۱۶ فلز

## چرا این بسته ساخته شد

بسته قبلی OQ-058 فقط الگوی انتخاب فلز در معامله و نمودار را مقایسه می‌کرد. برای انتخاب درست، ابتدا باید معلوم شود چندفلزی‌شدن ساختار کل اپ را چگونه تغییر می‌دهد و انتخاب‌گر معامله داخل کدام معماری قرار می‌گیرد.

خط مبنا، شل و وایرفریم قبلی با سه مقصد `خانه / معامله / خدمات` است. تغییر فقط وقتی پیشنهاد می‌شود که تعدد فلزها باعث ابهام، خطای انتخاب Asset یا ضعف مقیاس تا حدود ۱۶ فلز شود.

## مرز اصلی: مشترک یا فلز‌محور

| سطح | قرارداد پیشنهادی |
|---|---|
| شل و ناوبری اصلی | مشترک بین همه فلزها |
| احراز هویت، حساب، اعلان، پشتیبانی | مشترک |
| کیف تومان، واریز و برداشت | مشترک و جدا از پورتفوی فلزی |
| خانه | مشترک؛ خلاصه پورتفوی و ردیف هر فلز در همان صفحه |
| صفحه جزئیات دارایی | یک Template مشترک با Context جدا برای هر `assetId` |
| معامله | یک فلو و ماشین‌حساب مشترک؛ نرخ، دقت، حداقل، کارمزد، موجودی و status فلز‌ویژه |
| نمودار | یک Component مشترک؛ داده و Context فلز‌ویژه |
| خدمات | Hub مشترک؛ قابلیت و شرایط هر خدمت با `AssetCapability` فلز‌ویژه |
| دریافت فیزیکی | فلو مشترک؛ انتخاب فلز پیش از محصول و کاتالوگ/گرید/هزینه فلز‌ویژه |
| تاریخچه و رسید | فهرست مشترک؛ Label، Icon، Filter و فیلدهای رسید فلز‌ویژه |

اصل فنی/تجربه‌ای پیشنهادی این است: **صفحه جدا برای هر فلز نسازیم؛ Template مشترک را با `assetId` و پیکربندی هر فلز تغذیه کنیم.** جداسازی باید در Context و Rules باشد، نه در شل‌های موازی طلا/نقره/مس.

## گزینه ۱ — شل فعلی + جزئیات فلز

```text
خانه                  معامله                 خدمات
├─ ارزش کل فلزها      ├─ انتخاب فلز          ├─ دریافت فیزیکی → انتخاب فلز
├─ طلا                ├─ خرید / فروش         ├─ هشدار قیمت → انتخاب فلز
├─ نقره               ├─ مبلغ / وزن          ├─ هدیه → Capability-gated
├─ مس                 └─ Preview / Result    └─ اقساط → براساس قابلیت فلز
├─ کیف تومان
└─ تاریخچه

Tap روی هر فلز → جزئیات همان فلز → نمودار / خرید / فروش / دریافت فیزیکی
```

تغییر نسبت به وایرفریم قبلی: `کم`.

- سه Tab فعلی حفظ می‌شوند.
- Card تک‌فلزی خانه با خلاصه پورتفوی و ردیف فلزها جایگزین می‌شود.
- مقصد داخلی «دارایی» به جزئیات Contextual هر فلز تبدیل می‌شود.
- معامله و خدمات شل مشترک خود را حفظ می‌کنند و Asset-aware می‌شوند.
- در Release اول، Cardهای سه فلز روی خانه مستقیماً جزئیات را باز می‌کنند؛ صفحه فهرست مستقل وجود ندارد — D-215.

مزیت: بیشترین reuse، کمترین تغییر مدل ذهنی و کافی برای ۳ تا ۱۶ فلز.  
ریسک: با رشد واقعی کاتالوگ، نبود صفحه فهرست می‌تواند کشف فلز تازه را ضعیف کند و باید دوباره ارزیابی شود.

## گزینه ۲ — افزودن مقصد مستقل بازار

```text
خانه       بازار       معامله       خدمات
           ├─ همه فلزها
           └─ جزئیات فلز → نمودار / معامله / خدمات
```

تغییر نسبت به وایرفریم قبلی: `متوسط`.

- خانه و خدمات حفظ می‌شوند.
- Tab جدید «بازار» برای کشف، جست‌وجو و مقایسه ۳ تا ۱۶ فلز اضافه می‌شود.
- معامله همچنان مقصد مستقل و سریع باقی می‌ماند.

مزیت: بهترین کشف فلزهای تازه و مناسب رشد کاتالوگ.  
ریسک: در Release اول با سه فلز، نقش «بازار» و «معامله» هم‌پوشانی دارد و یک مقصد سطح اول تازه به شل اضافه می‌کند.

## گزینه ۳ — ساختار فلز‌محور

```text
خانه       دارایی‌ها       خدمات
           ├─ طلا → Hub طلا → نمودار / خرید / فروش / دریافت
           ├─ نقره → Hub نقره → نمودار / خرید / فروش / دریافت
           └─ مس → Hub مس → نمودار / خرید / فروش / دریافت
```

تغییر نسبت به وایرفریم قبلی: `زیاد`.

- Tab معامله حذف و اقدام معامله داخل Hub هر فلز قرار می‌گیرد.
- هر فلز نقطه شروع همه اقدامات خودش می‌شود.

مزیت: Context فلز در تمام مسیرها بسیار روشن است.  
ریسک: دسترسی مستقیم و پرتکرار به معامله ضعیف‌تر می‌شود، شل قبلی را می‌شکند و با زیادشدن فلزها تعداد Hubها و عمق Navigation بیشتر می‌شود.

## تصمیم تأییدشده

`Business decision`: **گزینه ۱ — حفظ شل فعلی و افزودن لایه دارایی چندفلزی** — D-120.

دلیل اصلی این است که چندفلزی‌شدن در سطح «داده، Context و Rules» اثر قوی دارد، اما هنوز دلیلی برای شکستن سه مقصد اصلی `خانه / معامله / خدمات` ایجاد نکرده است. تغییرهای ضروری و پراثر عبارت‌اند از:

1. بازطراحی Card خانه به پورتفوی فلزی و ردیف‌های Asset؛
2. ساخت Template جزئیات فلز و اتصال مستقیم Card خانه به آن؛
3. Asset-aware کردن معامله، نمودار، دریافت فیزیکی، تاریخچه و رسید؛
4. تعریف قابلیت‌ها از `AssetCapability` به‌جای فرض برابری طلا، نقره و مس.

`Business decision`: با D-215، مقصد داخلی «بازار/همه فلزها» نیز از Release اول حذف شد. نسخه ۳ و ۱۶ Asset فقط در آرشیو نگهداری می‌شود؛ انتخاب فلز در معامله و فیلتر تاریخچه این تصمیم را تغییر نمی‌دهند.

## رابطه با بسته قبلی OQ-058

انتخاب مدل معامله/نمودار داخل تصمیم ساختار کل اپ قرار می‌گیرد. اگر گزینه ۱ تأیید شود، پیشنهاد قبلی `انتخاب‌گر واحد + Sheet کامل` همچنان مناسب است، اما دیگر به‌تنهایی تصمیم معماری کل اپ محسوب نمی‌شود.

## نتیجه تصمیم مالک محصول

هر سه قرارداد تأیید شدند:

1. گزینه ۱ مسیر اصلی است؛
2. طبق اصلاح D-215، Card هر فلز در خانه مستقیماً جزئیات همان فلز را باز می‌کند و مقصد «بازار/همه فلزها» وجود ندارد؛
3. قاعده «Template مشترک + Context/Rules فلز‌ویژه» مبنای همه بخش‌هاست.

Navigation/IA/Content با D-120/D-215 همگام شدند. مقیاس ۱۶ فلز فقط در انتخاب‌گر معامله و Stress testهای مربوط حفظ می‌شود.

## Gate

`Complete` برای تصمیم ساختار کل اپ؛ Gate مرحله ۴ برای ادامه `Sufficient to proceed` است. زیرالگوی معامله/نمودار با D-121 و پیش‌فرض طلای معامله با D-123 بسته‌اند؛ OQ-059 قدم فعال معماری است.
