# اولویت‌بندی قابلیت‌ها

وضعیت: `Sufficient to proceed` — ترتیب طراحی و مرز قابلیت‌های اصلی Release اول توسط مالک محصول تأیید شده است؛ D-082.

## روش اولویت‌بندی

- اولویت بر پایه ارزش کاربر، اثر بر فعال‌سازی/ماندگاری/اعتماد، نقش در تمایز، ریسک مالی و وابستگی اجرایی تعیین می‌شود.
- امتیازها کیفی‌اند: `بالا`، `متوسط` یا `کم`. این روش از دقت عددی ساختگی در نبود داده واقعی جلوگیری می‌کند.
- ترتیب طراحی با ترتیب ساخت یکی نیست؛ قابلیت پرریسک می‌تواند زودتر برای حل وابستگی بررسی شود، حتی اگر دیرتر ساخته شود.
- قابلیت‌های افقی مانند اعتماد، شفافیت قواعد، پشتیبانی، اعلان و تاب‌آوری PWA داخل همه موج‌ها اجرا می‌شوند و Release جدا ندارند.

## قابلیت‌های افقی Release اول

- شفافیت نرخ، کارمزد، سقف، زمان و پیش‌نیاز نزدیک هر اقدام
- مجوزها، بانک کارگشایی، ریفاینری، ضرب و شواهد اعتماد قابل انتشار
- اعلان‌های عملیاتی، وضعیت اختلال و مسیر پیگیری
- پشتیبانی contextual برای عملیات حساس
- پروفایل، قوانین، محدودیت حساب و بازیابی
- نصب، به‌روزرسانی امن، مدیریت قطعی اینترنت و Android WebView

## بعد از Release اول

- باشگاه وفاداری و مکانیک امتیاز/سطح — OQ-034
- کد تخفیف و کمپین مرتبط — OQ-036
- وام با وثیقه، کارت پرداخت، چندفلزی، حساب VIP و سایر قابلیت‌های منتظر تصمیم طبق سؤال‌های باز مربوط

## قاعده اجرای موازی

`Business decision`: اقساط در موج ۶ طراحی تفصیلی می‌شود، اما بررسی شریک، قرارداد، اعتبارسنجی، جریمه و تسویه آن باید از موج ۱ به‌صورت موازی شروع شود تا Release اول به تصمیم بیرونی دیرهنگام وابسته نماند.

## نتیجه زیرمرحله

`Sufficient to proceed` — مرز قابلیت‌های اصلی Release اول و ترتیب طراحی آن‌ها مشخص است. جزئیات زمان‌بندی، ظرفیت تیم و تقویم انتشار در برنامه تحویل تعیین می‌شوند و مانع ورود به بازبینی وابستگی‌ها و ریسک‌ها نیستند.
