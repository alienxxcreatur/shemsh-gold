# ماتریس پوشش حالت‌های عملیات در Prototype

تاریخ: ۲۶ مرداد ۱۴۰۵ / 17 Aug 2026  
تصمیم مرتبط: D-193
Artifact: `artifacts/multi-metal-waves-1-and-3-wireframe.html`

## هدف

این سند مشخص می‌کند برای هر عملیات چه Stateهایی باید در ستون Review مستقل دیده شوند تا بررسی فقط به Happy path محدود نباشد. صفحه‌ها از یک الگوی بصری مشترک استفاده می‌کنند، اما «اثر روی موجودی»، «وضعیت پیگیری» و «اقدام بعدی» برای هر عملیات اختصاصی است.

## قرارداد پوشش

- `Observed fact` — Prototype پیش از D-193 تعداد ۴۱ صفحه/حالت در ۱۰ Accordion داشت و چند مسیر عمومی همیشه به نتیجه موفق می‌رفتند.
- `Business decision` — طبق درخواست مستقیم مالک محصول، Stateهای ضروری همه عملیات باید در ستون Review قابل انتخاب باشند، نه فقط خرید.
- `Design assumption` — متن‌ها، عددها و کدهای صفحات State نمونه‌اند و تصمیم مالی/حقوقی تازه ایجاد نمی‌کنند.
- `Risk` — نمایش یک State به‌معنی تأیید قاعده بیزینسی آن نیست؛ قواعد باز در OQ-003/OQ-005/OQ-006/OQ-020/OQ-040/OQ-043/OQ-044/OQ-053/OQ-054/OQ-061 همچنان Gate UI نهایی‌اند.

## موارد عمداً خارج از این توسعه

- `FL-CALC-001`: ماشین‌حساب اثر مالی و وضعیت تراکنش ندارد؛ State نرخ نامعتبر داخل همان صفحه کافی است.
- `FL-TRANSFER-001`: انتقال فلز طبق D-087 در نسخه فعلی حذف است و نباید با افزودن State دوباره وارد Scope شود.
- مدیریت کارت/شبا، تنظیمات پروفایل و اعلان‌ها: Validation/Empty state محلی دارند، اما Operation مالی مستقل نیستند.

## نتیجه QA ساختاری

- ۱۰۲ صفحه/حالت در ۱۴ Accordion.
- ۶۱ صفحه State تازه با یک Renderer مرکزی و محتوای اختصاصی هر عملیات.
- Duplicate، کلید مفقود، سناریوی بدون گروه، Config مفقود و مقصد Recovery نامعتبر: صفر.
- JavaScript Syntax: پاس.
- QA مرورگر روی `file://`: Reload خودکار طبق سیاست امنیتی Browser مسدود شد؛ Refresh و Review بصری دستی باز است.

## Gate

`Sufficient to proceed` برای Review وایرفریم Stateها.  
`Needs revision` برای قفل نهایی متن‌ها و اثرهای مالی/حقوقی تا بسته‌شدن سؤال‌های باز مرتبط.
