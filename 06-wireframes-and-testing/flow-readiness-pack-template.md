## ۳. ممیزی Eligibility و محدودیت

برای هر فلو صریحاً بررسی شود:

- حداقل/حداکثر سن و اهلیت قانونی
- مهمان، کاربر جدید، احرازنشده، تأییدشده و نشست منقضی
- کاربر حقیقی/حقوقی و تفاوت‌های احتمالی
- مالکیت موبایل، کارت، حساب بانکی یا داده ورودی
- محدودیت حساب، ریسک، تقلب، دستور قانونی و دسترسی منطقه‌ای
- پیش‌نیاز سرویس، سقف، موجودی، زمان، قرارداد و رضایت
- مرز دقیق eligibility و رفتار کاربر روی همان مرز
- امکان ادامه، مشاهده، تعویق، اعتراض، پشتیبانی یا خروج برای کاربر فاقد شرایط

هر مورد نامشخص باید در `open-questions.md` ثبت شود.

## ۴. قرارداد رفتاری فلو

| مرحله | Context ورود | پیش‌شرط | اقدام کاربر | پاسخ سیستم | مقصد موفق | مقصد Back/Cancel | داده حفظ‌شونده |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

قواعد:

- State داخلی فقط وقتی Screen مستقل می‌شود که کاربر باید اطلاعات تازه بفهمد یا تصمیم معناداری بگیرد.
- Success با مقصد معلوم، Feedback گذراست و CTA واسط نمی‌سازد.
- Back، ×، «بعداً»، Scrim و Gesture فقط با مقصد و اثر مشخص نمایش داده می‌شوند.
- ورود از Contextهای مختلف نباید کپی یا مقصد ساختگی ایجاد کند.

## ۷. ممیزی پیش‌دستانه

طراح/دستیار پیش از درخواست Review مالک محصول باید موارد زیر را مستقل بررسی و پیشنهادهای مهم را ارائه کند:

- خطاهای کاربر و سرویس، قطع اینترنت، پاسخ دیرهنگام و چندبار لمس CTA
- خروج و بازگشت، Refresh، Deep Link، انقضای نشست و حفظ state
- سوءاستفاده، تقلب، حریم خصوصی و نمایش اطلاعات حساس
- eligibility، الزامات حقوقی/انطباق و سناریوهای لبه
- دسترس‌پذیری، Screen Reader، اندازه متن، کنتراست و Focus
- Safe Area، صفحه کوچک، کیبورد، Gesture و هدف لمسی حداقل ۴۴/۴۸
- کپی تکراری، بدیهی، وابسته به Context ناموجود یا فاقد اقدام
- فرصت‌های ساده‌سازی، حذف Screen، Auto-advance و Progressive Disclosure
