# قرارداد محتوا و اصطلاحات وایرفریم — نسخه ۰.۱

تاریخ: ۱۹ اوت ۲۰۲۶  
دامنه: وایرفریم مرجع چندفلزی و فایل تخصصی ورود/احراز  
وضعیت: `Sufficient to proceed` برای ادامه پاک‌سازی Pre-Binance

## هدف

این قرارداد نام اشیا، مقصدها و وضعیت‌های پرتکرار را پیش از استخراج Patternهای بایننس یکدست می‌کند. این سند قانون مالی یا عملیاتی تازه نمی‌سازد و موارد Business-gated در D-206 را نهایی نمی‌کند.

## واژگان Canonical

| مفهوم | عبارت کاربر | استفاده نشود | قاعده |
|---|---|---|---|
| موجودی ریالی | `کیف تومان` | کیف پول، کیف پول تومان، کیف به‌تنهایی | عنوان Card، Sheet، روش پرداخت و پیام موجودی همیشه همین است. |
| مالکیت فلز | `دارایی طلا / نقره / مس` | کیف فلزی، کیف طلا/نقره/مس | خرید و هدیه به دارایی فلز اضافه می‌شوند؛ فروش از دارایی فلز کم می‌شود. |
| فهرست سوابق | `تاریخچه` | تاریخچه عملیات، تاریخچه یکپارچه | نام مقصد، Header و CTA همین عبارت است. |
| رکورد یک عملیات | `جزئیات عملیات` | رسید، رسید کامل، رسید چندفلزی | تاریخچه و اعلان، همین مقصد تطبیقی را باز می‌کنند. |
| محتوای نوع‌محور داخل جزئیات | `اطلاعات خرید / فروش / واریز / ...` | تکرار عنوان «جزئیات عملیات» در داخل صفحه | عنوان بخش داخلی براساس نوع عملیات تغییر می‌کند. |
| عملیات خدماتی آغازشده | `درخواست` | سفارش، پرونده یا عملیات به‌جای هم بدون Context | دریافت فیزیکی و موارد خدماتی تا وقتی قرارداد مستقل ندارند «درخواست» هستند. |
| تعهد خرید اقساطی | `قرارداد` | درخواست، طرح یا سفارش به‌جای قرارداد ثبت‌شده | فقط پس از فعال‌شدن خرید اقساطی استفاده می‌شود. |
| مرکز قابلیت‌ها | `مرکز خدمات` / `مرکز هدیه` | Hub | واژه داخلی انگلیسی در UI و عنوان Review نمایش داده نمی‌شود. |

## وضعیت‌های Canonical

| وضعیت | کاربرد |
|---|---|
| `موفق` | عملیات مالی ساده که نهایی شده است؛ مانند خرید، فروش و واریز. |
| `ناموفق` | تلاش ثبت‌شده‌ای که به نتیجه نهایی مطلوب نرسیده است. |
| `نتیجه نامشخص` | درخواست ارسال شده اما نتیجه مالی قطعی نیست؛ از «در حال انجام» جداست. |
| `ثبت‌شده` | درخواست دریافت/برداشت پذیرفته شده اما چرخه عملیاتی آن ادامه دارد. |
| `در حال نهایی‌شدن` | معامله ثبت شده و نتیجه نهایی هنوز آماده نیست. |
| `در حال آماده‌سازی` | دریافت فیزیکی یا هدیه وارد آماده‌سازی شده است. |
| `واریزشده` | مبلغ برداشت به حساب بانکی مقصد رسیده است. |
| `پرداخت‌شده` | قسط پرداخت و در قرارداد ثبت شده است. |
| `ارسال‌شده` | هشدار قیمت ارسال شده است؛ عبارت فنی «تحریک‌شده» استفاده نمی‌شود. |
| `لغوشده / منقضی / تسویه‌شده / فسخ‌شده` | پایان مشخص چرخه همان Object. |

## قواعد عنوان و توضیح

- Badge وضعیت و عنوان نباید یک معنا را تکرار کنند؛ با Badge `موفق`، عنوان «خرید طلا انجام شد» است، نه «با موفقیت انجام شد».
- صفحه موفق تاریخی توضیح عمومی «عملیات با موفقیت ثبت شد» ندارد؛ عنوان، Anchor و فیلدهای نوع‌محور کافی‌اند.
- Label ثابت `اثر عملیات` استفاده نمی‌شود. فقط در حالت مبهم، شکست، رزرو، قفل یا جبران، `وضعیت موجودی` نمایش داده می‌شود — D-209.
- زمان و کد پیگیری فقط در صورت وجود Record نشان داده می‌شوند؛ داده غایب ساخته نمی‌شود — D-207/D-208.
- CTA مقصد با فعل روشن نام‌گذاری می‌شود: `مشاهده تاریخچه`، `مشاهده کیف تومان`، `مشاهده دارایی` و `بازگشت به خانه`.

## پاک‌سازی اجراشده

- نام کیف ریالی در Card، Sheet، واریز، برداشت، معامله، اقساط و هدیه به `کیف تومان` تبدیل شد.
- اصطلاح کیف فلزی در خرید و هدیه با `دارایی فلز` جایگزین شد.
- Header تاریخچه به `تاریخچه` و مقصد رکورد به `جزئیات عملیات` یکدست شد.
- عنوان بخش‌های نوع‌محور از «جزئیات ...» به «اطلاعات ...» تغییر کرد تا با عنوان صفحه تکرار نشود.
- اشاره‌های کاربر به رسید جدا، رکورد، دفترکل، status، Hub، Quote و U2 حذف یا بازنویسی شد.
- توضیح موفقیت عمومی و Row خالی/تکراری موفقیت حذف شد.
- وضعیت‌های Reviewer با وضعیت واقعی صفحه هماهنگ شدند.

## مرز Reviewer و کاربر

- شناسه‌های `WF-*`، شمار Inventory و راهنمای تست فقط در پنل دسکتاپ Review باقی می‌مانند و داخل قاب موبایل نمایش داده نمی‌شوند.
- عبارت‌های فنی لازم در کد، Class و شناسه داخلی مشمول Copy کاربر نیستند.

## موارد باز

- `Design assumption` — Copy دریافت فیزیکی، اقساط، هدیه، سفارش/هشدار، مجوزها و پشتیبانی تا Review بیزینس طبق D-206 موقت است.
- `Open question` — کارمزد، سقف، SLA، متن حقوقی و حسابداری نهایی نباید از متن وایرفریم قطعی برداشت شوند.
- `Risk` — QA بصری مستقیم فایل محلی در مرورگر داخل برنامه به‌دلیل سیاست `file://` انجام نشد؛ بازبینی صفحه‌های نماینده در PB-5 الزامی است.

## Gate

- نام متناقض شناخته‌شده برای `کیف تومان / دارایی فلزی / تاریخچه / جزئیات عملیات`: صفر در سطح کاربر وایرفریم مرجع؛
- Copy داخلی شناخته‌شده در سطح موبایل: صفر؛
- JavaScript Parse: پاس؛
- QA بصری: باز و منتقل‌شده به PB-5؛
- ارزیابی: `Sufficient to proceed`.
